# Смена

Рабочий MVP планирования смен ресторана. Next.js App Router, React, TypeScript, Tailwind CSS 4, Motion, Lucide, date-fns и SQLite (встроенный `node:sqlite`). В исходном репозитории не было файлов или существующих библиотек.

## Запуск

Нужен **Node.js 24+**. Внешние сервисы и ключи для демо не требуются.

```bash
npm ci
npm run dev
```

Откройте приложение на порту **3000**. На экране входа выберите «Открыть демо менеджера» или «Я сотрудник». Демо переключает реальные серверные сессии между менеджером и Анной Смирновой; данные сохраняются в SQLite. Это открытое демонстрационное пространство, а не регистрация пользователей.

Первый запуск создаёт `.data/smena.sqlite`, команду из 12 сотрудников, доступность, смены, почасовую потребность и пожелания на текущую неделю. Дата ресторана определяется в `Asia/Tashkent` (UTC+5). Интервалы MVP ограничены одним днём, 08:00–23:00, с шагом один час.

```bash
npm run typecheck
npm test
npm run build
npm start
```

Для браузерных тестов нужен Chromium:

```bash
# По умолчанию используется /usr/bin/chromium.
# Если браузер установлен в другом месте, задайте CHROMIUM_PATH.
npm run test:e2e
```

E2E запускает отдельный сервер на порту 3100, использует `.next-e2e` и изолированную базу `.data/e2e-*`, не затрагивая демонстрационные данные. Тестируется полный сценарий: доступность → пожелание → подбор → предложение → принятие, сохранение после перезагрузки, ограничения ролей, запрет пересечений и мобильная навигация.

## Экраны

**Менеджер:** обзор, недельное расписание, дневная временная шкала, почасовая потребность и баланс, команда и профили, входящие пожелания, уведомления, журнал решений. Доступны поиск, фильтры зон/статусов, CSV-экспорт, создание/редактирование/отмена смен, предложения сотрудникам и публикация с уведомлениями. Перед назначением есть подтверждение.

**Сотрудник:** мой день, мои смены, недельная доступность, пожелания, ответы на предложения и уведомления. Мобильная версия использует карточки и сворачиваемую навигацию.

## Как проверить сценарий вручную

1. Войдите как сотрудник. Откройте «Доступность», выберите следующую неделю, включите понедельник 09:00–21:00 и сохраните.
2. Отправьте пожелание на этот день.
3. Переключитесь в панель менеджера. Откройте «Добавить смену», выберите этот понедельник, кухню, 09:00–15:00.
4. Выберите Анну: рядом указаны причины рекомендации. Оставьте «Сначала предложить сотруднику» и подтвердите отправку.
5. Переключитесь в кабинет сотрудника и примите предложение.
6. Смена будет подтверждена. Менеджер увидит решение в журнале, сотрудник — своё расписание. Перезагрузка сохраняет изменения.

Пожелание и смена — разные сущности. Принятие пожелания уведомляет сотрудника и учитывается при ранжировании; само по себе оно не отменяет и не назначает смену. При изменении доступности существующие смены сохраняются, а несовпадения отображаются как конфликты.

## Подбор

Допуск: нужная позиция, доступность на весь интервал, отсутствие пересечений (включая ожидающие предложения), не более 12 ч в день и лимита профиля в неделю (40 ч в демо), не менее 11 ч между сменами. Ранжирование: `100 − часы недели + 5 × ожидающие пожелания − 2 × ранее учтённые пожелания`. Менеджер выбирает любого допустимого кандидата. Сервер повторно проверяет ограничения в транзакции, в том числе при принятии предложения и редактировании.

Покрытие потребности — минимальное количество подтверждённых сотрудников в каждом часу интервала. Ожидающие предложения не считаются подтверждённым покрытием. Интервалы потребности одной зоны не могут пересекаться.

## Данные и доступ

Сущности: `User`, `EmployeeProfile`, `ManagerProfile`, `Availability`, `Shift`, `ShiftRequest`, `StaffingNeed`, `Position`, `Notification`, `DecisionLog`. Пользователи и сессии находятся в отдельных таблицах; профили и рабочие сущности сохраняются в таблицах SQLite в JSON. `Position` — фиксированный справочник трёх зон.

API проверяет роль на сервере. Сотрудник получает только свои смены, доступность, пожелания и уведомления. Токены сессий случайные, хранятся в базе в виде SHA-256, cookie — HttpOnly и SameSite=Lax. Пароли хэшируются через scrypt с индивидуальной солью. Вход ограничен по частоте в рамках процесса. Рабочие изменения и журнал записываются транзакционно. Открытые клиенты обновляют данные каждые 15 секунд и при возвращении в окно.

Для входа с паролем установите `MANAGER_PASSWORD` и/или `EMPLOYEE_PASSWORD` через защищённые переменные среды (минимум 12 символов), затем выполните:

```bash
npm run accounts:sync
```

Учётные записи: `manager@smena.local`, `employee1@smena.local`. Скрипт не выводит пароли и отзывает текущие сессии этих аккаунтов. Без заданных паролей создаются случайные, неизвестные пользователю пароли — используйте явный демовход.

Перед использованием реальных данных задайте `DEMO_MODE=false` и перезапустите сервер. Не храните настоящие данные при включённом деморежиме. SQLite рассчитан на один сервер с постоянным диском; для serverless/нескольких реплик потребуется перенос в Postgres/Supabase и полноценное управление пользователями. В MVP нет регистрации, восстановления пароля, нескольких ресторанов, email/push-рассылки и расчёта зарплаты. Уведомления работают внутри приложения. Публикация информирует сотрудников о подтверждённых сменах; она не утверждает ожидающие предложения автоматически.

## Структура

- `app/api` — авторизация, получение состояния и команды с проверкой прав.
- `lib/db.ts` — схема, сессии, начальные данные, транзакции.
- `lib/recommend.ts` — подбор, покрытие и обнаружение конфликтов.
- `components/smena-app.tsx` — навигация и основные экраны.
- `components/panel-view.tsx` — назначение, подтверждение и детали.
- `components/availability-editor.tsx`, `day-view.tsx`, `login.tsx`, `ui.tsx` — специализированные и общие компоненты.
- `app/globals.css`, `app/reference-theme.css`, `docs/design-system.md` — визуальные токены и компоненты.
